## What the web excludes/includes, and how Android matches it

- **Movies, Recently Added, home film picks**: web reads `library.movies` only (`groupLibrary` already excludes `docu`). Android's `MagazineHome.kt` was already scoped to the Movies shelf; the one place that wasn't was `TitlePageCandidates.filmsOf(shelves)` (used by a film's Similar/franchise tab), fixed to read the Movies shelf alone.
- **Home page rows**: `home-shelves.js`'s `homeShelves()` only ever builds `latestMovies`/`latestSeries`/`latestCourses` and an underway loop over `[...library.series, ...library.tutorials]` — no Documentaries anywhere. `homeRowsOf`'s per-shelf "Latest X" loop and the new `collectionsForNextUp` both exclude the Documentaries shelf for the same reason (a documentary has no "next episode").
- **Tally** (rail masthead / Settings tablet tally): web's own three lines never include documentaries; `LibraryTally.kt`'s `EXTENT_NOUNS` map already excludes them (untouched, pre-existing test `aShelfThisFunctionDoesNotNameIsLeftOut` already covered it).
- **Tab bar**: Documentaries is the one shelf `shelvesOf` never omits, even at zero — matches the web never hiding a department. Every other shelf keeps the pre-existing (Android-only) omit-when-empty behaviour, which the phase wasn't asked to change.
- **Department page card behaviour**: web's `renderDocumentariesDept` wires every row to `cx.play`, not `cx.openFilm` — verified by reading `department-pages.js:97` directly. Android's screen does the same (`onPlay` everywhere except the "All N" card, which opens the collection).
- **`locationOf`** (search line) and **grouping** (`collections()` reused with `CollectionKind.COURSE`) were read from the web source line-for-line and matched exactly, including the parts that surprised me (a documentary's search line is just its year, even inside a folder).

## Series count discrepancy (coordinator's flag)

Investigated and resolved: not a Documentaries bug. The web preview process (`bun run preview`) had been running since before the channel index's last refresh and was serving a stale copy (it copies the index once at startup). Restarting it made the web report the same `ep`/documentary counts Android does. Verified independently against the raw sqlite (`ep`: 1511 complete + 1 pending, zero overlap between `ep`-kind and `docu`-kind show names) and via the live `/api/sets` before/after the restart. Added `ShelvesTest.aDocumentaryNeverJoinsASeriesEvenWhenItSharesAShowNameAndHasSeasonEpisodeFields` to pin the actual invariant (kind, not folder name or season/episode fields, decides the shelf).

## TV decision

TV shares `shelvesOf`/`catalogTabsOf`/`mastheadSplitOf`, all generic over shelves, so Documentaries reaches the TV masthead and tab index space for free — TV "gets the tab too," per the plan's architecture note. `DepartmentOrShelfWall` (`TvDepartmentPages.kt`), TV's per-shelf front-page dispatcher, previously fell to an `else` branch for anything not "Movies" and treated the shelf's collections as a show/course front page with `kind = if (title == "Tutorials") TUTORIAL else EPISODE` — for Documentaries that mislabels every folder and, via `filterIsInstance<Entry.Collection>()`, silently drops every standalone single. Fixed by excluding `DOCUMENTARIES` from that branch; it now falls to `TvShelfWall`, the same plain wall any shelf without a front page gets — a mixed `Entry.Film`/`Entry.Collection` list `TvShelfWall`/`TvEntryPlate` already render generically. No TV department page was built, per the plan. `TvCatalogBody`'s Latest/Home row building needed no change: it reads `homeRowsOf`, already fixed at the source.

## Deviations / judgment calls

- **TV's own saved-tab index** (`TvCatalogScreen.kt`'s `chosen`) has the same by-index restore risk as the phone's did, but I left it alone: fixing it touches `rememberTvCatalogRestore`'s focus/back-stack machinery, which the plan doesn't ask for and which risks the delicate remote-control focus restoration for a one-time, self-healing mismatch (one tab off, until the next tap) that only firing on this specific upgrade for a process that survives it. Flagging rather than silently taking it on.
- **Search** (`SearchGroups.kt`, `SearchFilter`) has no Documentaries bucket; a `docu`-kind hit now matches none of `MOVIES`/`SERIES`/`TUTORIALS` and drops out of search results (before this phase it surfaced as a film, via the old `docu → MOVIE` fallback). The web has a dedicated documentaries search group (`search-view.js:87`). Not in this phase's Related Code Files, Requirements, or acceptance criteria; flagging as a follow-up rather than expanding scope.
- Documentary collections reuse `CollectionKind.COURSE` rather than a new enum value — its "chapters" line, no season wall, and list-only view choice all already match the web's own treatment of a documentary folder (chapters, not seasons); a new enum value would have meant touching a handful of `CollectionKind == SHOW/COURSE` call sites for no behavioural difference.
