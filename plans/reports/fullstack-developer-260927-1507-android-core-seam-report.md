## What changed

**New module `:core:testing`** (`android/core/testing/`):
- `FakeCore.kt` (446 lines) — the one fake of `CoreInterface`, replacing 6 per-module fakes (808 combined lines) and 5 `mockk<CoreClient>` doubles. Every constructor param is a settable `var`; a handful of methods needing per-test dynamic behaviour (`catalogFacts`, `requestCode`, `signIn`, `checkPassword`, `refreshLibrary`) expose an overridable `...Answer` lambda field on top of the default. Real-contract cases: `read`/`totalSize` throw `CoreException.NotFound` past a set's end or for an id outside `knownSetIds` (default `null` = every id known, preserving every pre-existing playback test that never populated a set catalog); `revokeSession("0")` always throws `CoreException.NotAuthorized` (crates/mediagram-core/src/api/sessions.rs); every failure field is a `CoreException`-capable `Throwable?`.
- `FakeCoreHandle.kt` — `interface FakeCoreHandle : CoreInterface, AutoCloseable`, what a `CoreProvider` build lambda must return; lets a test class override specific calls with one `by` delegate instead of two.
- `FakeCoreProvider.kt` — one `CoreProvider` fake (`set()` to swap the published core) plus two zero-cost factory-function aliases, `ResolvedCoreProvider`/`CatalogCoreProvider`, so most of the ~30 existing call sites needed no rename.
- `CoreContract.kt` — abstract JUnit4 suite, 7 cases needing neither network nor a signed-in session (unknown-set `read`/`totalSize` → `NotFound`, empty `listSets`, `revokeSession("0")` refused, create/choose/delete a local profile). Each case documented with why it's offline-safe.
- `src/test/.../FakeCoreContractTest.kt` — runs the suite against `FakeCore(knownSetIds = emptySet())`; all 7 pass. Mutation-checked: disabling the NotFound-past-end branch in `read()` failed `readingAnUnknownSetIsNotFound` as expected; reverted.
- `android/core/rust/src/androidTest/kotlin/rust/RealCoreContractTest.kt` — runs the same suite against a real `Core` on a fresh per-test data dir, next to `CoreLoadsTest`; compiles (`:core:rust:compileDebugAndroidTestKotlin` green). Not run — tablet is the lead's.

**`CoreClient`/`DefaultCoreClient` deleted** (`android/core/data/src/main/kotlin/`). `CoreProvider.kt`: `StoredCoreProvider` is now `class StoredCoreProvider<T>(...) : CoreProvider where T : CoreInterface, T : AutoCloseable` (added `import uniffi.mediagram_core.CoreInterface`); `core`/`awaitCore`/`coreOrNull` now expose `CoreInterface`. The close fence moved in as `closeFully(core: T) { core.retireLocalState(); core.close() }`, called from both `closeHeld()` and the unpublished-candidate path in `discard()` (the old `CoreClient.close()` did both steps internally for both paths — moving the fence out meant applying it in both places it used to be implicit). `app/.../di/CoreModule.kt` now passes `Core(...)` straight to `StoredCoreProvider`, no wrapper.

**12 production callers** moved onto `CoreInterface` directly: core:data (`CatalogRepository`, `LibraryEvents`, `PlayerPreferences`, `WatchStateRepository`, `WatchSync`, `CatalogEnrichmentFetcher`), core:playback (`MlibDataSource`, `MlibDataSourceFactory`, `PlayerFactory`, `CacheDataSourceWriter`, `SetChunkSource`), feature:system (`SystemUiState`, `SystemViewModel` — doc only). The 7 unsigned-typed calls convert at each call site: `refreshLibrary`/`refreshCatalog`/`totalSize` via `.toULong()`/`.toInt()` on the unsigned result (no behaviour change — same bit pattern, values always small in practice); `read`'s offset/len via `.toULong()`/`.toUInt()`; `fetchMissing`'s `backdropWidth` via `.toUInt()`; `person`/`fetchPortrait`'s id params via `.toULong()`. `createProfile`'s `kids` default is gone from the interface; both callers (`WatchStateRepository`, the shared fake) already passed it explicitly.

**Every module's tests** now build on the shared fake (`testImplementation(project(":core:testing"))` added to core:data, core:playback, feature:catalog, feature:setup, feature:system, ui-mobile, ui-tv). ~25 `object : CoreClient by FakeCore()`-shaped overrides became `CoreInterface by FakeCore()` (or `FakeCoreHandle by X` where `close()` needed overriding too — `CoreProviderReplaceTest`, `CoreCandidateCleanupTest`'s cancelled-validation case). Local test-fixture class names with "CoreClient" in them renamed (`StateCoreClient`→`StateCore`, `SyncCoreClient`→`SyncCore`, `PreferenceCoreClient`→`PreferenceCore` — `git grep -n CoreClient -- android` must find nothing, including in identifiers, not just production code).

**5 `mockk<CoreClient>` doubles → `FakeCore`**: `MobileAppFixture.kt`, `SettingsProfileRetryTest.kt`, `FailureDiagnosticsTest.kt`, `TvAppFixture.kt`, `SystemViewModelTest.kt`. `MobileAppFixture` needed the dynamic `...Answer` hooks (phone-number-indexed token, `authorized` flip on sign-in success) — its consumer `MobileAppTest.kt` used `coVerify { fixture.core.X(...) }` on the mock, which doesn't exist for a plain class, so those became assertions against `FakeCore`'s own call-tracking fields (`requestedPhones`, `signInCalls`/`passwordChecks` tracked by the fixture itself, `authorizedReads`, `signedOut`) — same or better precision (exact args in order, not just a count). `SettingsProfileRetryTest`/`FetchViewModelTest`/`CatalogEnrichmentFetcherTest` etc. needed 3 counters `FakeCore` didn't have yet (`listCalls`, `profilesCalls`, `catalogFactsCalls`) — added.

**Real-contract fixes applied where tests previously asserted the *wrong* fake behaviour**: none found. Grepped every test file for `revokeSession("0")` accepted, read-past-end returning bytes, totalSize-of-unknown returning 0 — none existed; the old per-module fakes happened not to be exercised on those paths. No production code depended on a wrong fake behaviour; nothing to STOP on.

**Retry test moved**: `DefaultCoreClientCloseTest.kt` (2 tests, one for "retire fails → retry" and one for idempotent double-close) is deleted. The double-close case is subsumed by `CoreProvider`'s own bookkeeping (nothing can call `close()` twice on an already-fully-closed core through the provider — `built.value`/`pendingClose` both go `null` on success). The retry case is *not* subsumed automatically — added `CoreAccountResetTest.aFailedRetirementIsOwnedUntilRetryAndDoesNotPermitDeletionOrReopening`, sibling to the existing close-failure-retry test, asserting `retireLocalState()` failing leaves the handle open (`closeCalls == 0` while it fails) and retries correctly once cleared.

**Docs**: `docs/system-architecture.md` — module map row for `core:data` and new row for `core:testing`; module-direction paragraph now names `core:testing` and `CoreInterface`/`CoreProvider`; close-fence paragraph rewritten off `DefaultCoreClient.close()` onto `StoredCoreProvider`'s fence, `CoreInterface`/`AutoCloseable`/`FakeCoreHandle`. `docs/project-changelog.md` new top entry `## 0.68.13`. `core/data/build.gradle.kts` and `core/rust/build.gradle.kts` and `feature/player/build.gradle.kts` comments naming `CoreClient` fixed.

## Code-review fixes (second pass)

Applied after the coordinator's review, same worktree, still uncommitted:

1. **M1** `SystemViewModelTest.kt` — restored `coVerify(exactly = 2) { CacheProvider.occupancy(...) }` in `aCacheOpenFailureDoesNotEscapeTheSnapshotCollector`, dropped along with the mockk imports during the mockk→FakeCore conversion.
2. **L1** `CoreProvider.kt` — `closeFully` had lost `DefaultCoreClient`'s `uniffiIsDestroyed` guard. Real risk: `retireLocalState()` on an already-destroyed generated `Core` throws (`callWithHandle` checks a call counter), so if `close()` ever flips destroyed and then itself throws, every retry's `retireLocalState()` would throw forever. Fixed type-agnostically: `StoredCoreProvider` now remembers, per the core `pendingClose` currently holds, whether `retireLocalState()` already succeeded (`pendingCloseRetired`), and a retry that only needs `close()` again skips it. Added `(core as? Core)?.uniffiIsDestroyed == true` as an early return in both `closeHeld` and `closeFully`. New tests: `CoreAccountResetTest.aRetryAfterAFailedCloseDoesNotRepeatAnAlreadySuccessfulRetirement` (close throws once → retry succeeds, `retireCalls == 1`); `CoreCandidateCleanupTest`'s `persistenceFailure` now asserts `rejected.retireCalls == 1` (discard retires before closing an unpublished candidate too).
3. **M2** — `CoreContract` only ever reads an *unknown* set, so the original mutation check couldn't have exercised the past-a-known-set's-end branch. Added `crates/mediagram-core/src/api/read_tests.rs::a_read_at_the_sets_total_size_is_not_found` (offset == total → `NotFound`, checked before any network call — `read.rs:52`; `cargo test -p mediagram-core` green, 373 lib tests now, was 372) and `core:testing`'s new `FakeCoreTest.readingPastAKnownSetsEndIsNotFound` (a *known*, positively-sized set read at its own end). Redid the mutation check honestly: disabled only the past-end branch (not the unknown-set branch) in `FakeCore.read`, confirmed `FakeCoreTest` — not `CoreContract` — failed, reverted.
4. **M3** `FakeCore.kt` — the default `knownSetIds = null` meant `totalSize(unknown)` answered `0` instead of `NotFound`, so the contract was only proven against a fake explicitly configured with `knownSetIds = emptySet()`, not the default one every other test builds. `knownSetIds == null` now derives known ids from `sets` when any are configured, or from whether `totalSize > 0` otherwise (every playback test that reads through this fake configures `totalSize` but never a `sets` catalog — preserved with zero test changes, confirmed by a full run of every module). A completely unconfigured `FakeCore()` now has no known set at all. `FakeCoreContractTest` runs against a plain `FakeCore()`.
5. **L2** `MobileAppTest.kt` — restored "signed out exactly once" via a new `FakeCore.signOutCalls` counter (`assertEquals(1, fixture.core.signOutCalls)`).
6. **L4** `FakeCore.createProfile` — ids are now a monotonic counter (`p${nextProfileId++}`), not derived from the current list's size, so a create after a delete cannot reissue a live id. A blank/whitespace-only name answers `null`; internal whitespace collapses — both matching `crates/mediagram-core/src/state/profiles.rs`'s `clean_name` (:145). Return type is now the correctly-nullable `Profile?`. New `CoreContract.aBlankProfileNameIsRefused` case (offline-safe: local `state_db` write, no network).
7. **L5** `FakeCore.kt` header doc — no longer claims every failure is a `CoreException`; now names which fields are (all the settable `Throwable?` ones) and which aren't (`refreshFails`, `requestCodeFails`, `signInFailures`/`passwordFailures` running out, `accountAnswer == null` — all a plain `IllegalStateException` via `error(...)`, matching what the per-module fakes this replaced did).
8. **L7** — `TvAppFixture.kt`'s "that mock is stubbed" → "that fake is configured" (it's a `FakeCore`, not a mock). `CoreModule.kt`'s KDoc no longer claims to be the only place `Core` is *named* outside the provider (untrue now that `CoreProvider`'s own `isAlreadyDestroyed` names it too, from item 2) — reworded to "the only place production code *constructs*" it, which stays true.
9. Left L3 (use-after-close modelling) and `LibraryFlowFixture`'s `mockk<CoreProvider>` tripwire untouched, as directed.
