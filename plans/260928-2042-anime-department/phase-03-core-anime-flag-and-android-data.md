# Phase 3 — Core: the rule in Rust, `anime` on every catalog row, Android data layer

## Overview

Android's catalog comes from the Rust core over UniFFI. This phase ports the web
rule to Rust (held to the web's fixture), attaches `anime: bool` to every
`SetSummary` the core lists, regenerates the Kotlin bindings, and maps the field
onto `MediaSet`. Nothing on an Android screen changes yet; phase 4 uses it.
Kotlin never re-implements the rule — it reads the boolean.

## Requirements

- `mediagram_core::shows::is_anime(kind, genres, original_language, forced) -> bool`,
  line-for-line the web's `isAnime` (`web/src/catalog/anime.ts`).
- `mediagram_core::shows::anime_overrides(conn) -> HashMap<String, bool>` keyed by
  poster key; empty when the table is absent (index before v11); NULL rows skipped.
- `crates/mediagram-core/tests/shared_anime_fixtures.rs` runs every case of
  `web/test/fixtures/anime/cases.json` (the web is authoritative: a case that
  only passes after a change here does not belong in the fixture).
- `SetSummary.anime` set in `store::editorial::enrich` for listings and single
  lookups alike (`list_sets`, `media_set`), using the index's facts **or** the
  device's fetched sidecar facts (same `or_insert` fallback as genres), and the
  index's overrides only.
- `MediaSet.anime: Boolean = false`, mapped in `toMediaSet`.
- Native `.so` rebuilt with the bindings; no device install from this phase
  without it (a stale `.so` against new bindings fails at launch).

## Architecture

```
index library.db ─┐ shows::genres / shows::facts (+ original_language) ──┐
device sidecar ───┘  (fallback per poster key, editorial.rs:83-101)       │
index anime_overrides ─> shows::anime_overrides ─────────────────────────┤
                                                                          ▼
editorial::enrich loop: summary.anime = is_anime(&summary.kind, &summary.genres,
                         facts[key].original_language, overrides[key])
        │ UniFFI SetSummary.anime (Boolean)
        ▼
CatalogRepository.toMediaSet ──> MediaSet.anime ──> (phase 4) shelvesOf
```

`ShowFacts` gains `original_language` rather than a new per-row query:
`facts()` is already read once per listing and already merged with the sidecar,
so the fetched-language fallback comes free.

## Implementation Steps

1. `shows/anime.rs` + unit tests; `shared_anime_fixtures.rs` → `cargo test -p mediagram-core --test shared_anime_fixtures`.
2. `ShowFacts.original_language` + `facts()`; fix/add `facts.rs` tests.
3. `SetSummary.anime`; `enrich` computes it; `editorial_tests.rs` cases.
   `cargo test -p mediagram-core` and `cargo clippy --all-targets -- -D warnings`.
4. `scripts/generate-android-bindings.sh` (needs `ANDROID_NDK_HOME` + cargo-ndk; it
   also cross-builds the `.so` for all four ABIs into `android/core/rust/src/main/jniLibs`).
   Commit the regenerated `mediagram_core.kt`; the `.so` files stay untracked.
5. `MediaSet.anime`, `toMediaSet`, `CatalogRepositoryTest`.
6. `scripts/check.sh` green (gradle `testDebugUnitTest` compiles every module against the new record).
7. Docs, changelog, patch bump; commit.

## Success Criteria

- [ ] `shared_anime_fixtures.rs` passes every web fixture case with no case edited for Rust.
- [ ] Same verdicts as the web on real data: checked end to end in phase 4 (tablet Anime count = web Anime count over the same published index). No probe binary is added for it.
- [ ] A v10 index and an index with no overrides table list with `anime = false` and no error.
- [ ] Sidecar-only facts (device-fetched) with `ja` + Animation mark the title anime.
- [ ] Kotlin `MediaSet.anime` round-trips from `SetSummary`; `scripts/check.sh` green.
- [ ] `.so` rebuilt in the same working tree as the bindings.

## Risk Assessment

| Risk | L×I | Mitigation |
|---|---|---|
| Rust and TS rules drift | L×H | One fixture, owned by the web, run by both suites; any rule change starts there. |
| Stale `.so` installed with new bindings → crash at launch | M×H | Bindings script rebuilds the `.so`; phase 4's device steps start with `scripts/build-android-core.sh`. |
| `editorial.rs` / `summary.rs` cross the 200-line limit | L×L | ~187 and ~176 after the change; if not, move `resolve_artwork` (:153-176) to `resolve.rs`. |
| Web and core disagree on facts source (device sidecar has languages the index lacks) | L×L | Deliberate and pre-existing: the web has no sidecar (`editorial.rs:76-81` documents it); with phase 1's backfill published the index has them anyway. |

**Rollback:** revert; regenerate bindings; rebuild `.so`. No data involved.

## Security Considerations

None new: reads the index read-only (`open_ro`), no network.
